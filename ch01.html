shell 先按空白切词，第一个词是程序名 13:39

shell 拿到一行命令，先按空白切成一串词。第一个词是要运行的程序，后面的都是参数。

打个比方切词就像拿剪刀沿着空格剪纸条。引号是贴在纸条上的胶带，胶带盖住的空格不剪。反斜杠是只盖一个字的小胶带。

打开终端看到的那一小段叫提示符（prompt）。它表示 shell 在等你输入。

想让一个参数里带空格，有两种写法 16:04。

  • 引号：'My Photos' 或 "My Photos"。引号里的空格不切。
  • 转义：My\ Photos。反斜杠告诉 shell，下一个字符别当特殊字符。

sort 默认按字典序，uniq 只合并挨着的行 32:43

这几个小工具各管一件事。最容易错的有两点。sort 默认按字典序排，uniq 只看相邻的行。

bash · 本机实测
$ printf 'a\n3\n31\nb\nx\n1\n4\n' > data   # 造 7 行测试数据
$ sort data | tr '\n' ' '      # 字典序逐个字符比，31 排在 4 前面
1 3 31 4 a b x
$ sort -n data | tr '\n' ' '   # -n 才按数值，字母行被当成 0
a b x 1 3 4 31
$ printf 'bob\nann\nbob\n' | uniq -c          # 两个 bob 不挨着，各数一次
      1 bob
      1 ann
      1 bob
$ printf 'bob\nann\nbob\n' | sort | uniq -c   # 先排序，同名才挨在一起
      1 ann
      2 bob

打个比方uniq 像排队点名，只和前一个人比。前后两人同名才算重复。中间隔了一个人，它就认不出来。所以先用 sort 让大家按名字站好。

命令作用要点
cat file打印文件内容讲义推荐带语法高亮的 bat
sort file按行排序默认字典序。加 -n 才按数值
uniq file去掉相邻的重复行4 4 4 3 4 变成 4 3 4。sort -u 一步到位
head / tail打印开头或结尾几行默认 10 行，-n 数字 指定
为什么会在这里踩坑

统计次数时忘了先 sort，同一个名字会被数成好几段。上面两个 bob 就是这样。正确写法是 sort | uniq -c。按次数排序时也要加 -n，不然 10 会排在 9 前面。

grep 挑出匹配的行，sed 改写每一行 35:39

grep 只把匹配模式的行打印出来。sed 按规则改写每一行。两者的模式都是正则表达式。

bash · 写法示意
$ grep -r TODO src/              # 搜的是文件内容，不是文件名
$ sed 's/grep/john/' notes.md    # 不加 -i，只打印结果，文件不变
$ sed -i 's/grep/john/g' */*.md  # -i 直接改文件，g 表示一行里全换

打个比方grep 像拿荧光笔扫一遍，只抄下带关键词的行。sed 像编辑器里的“查找替换”，但能一口气改一堆文件。

grep 加 -r 会钻进子目录，把整棵目录树都搜一遍。正则表达式在第 9 讲细讲。

sed 是一个能编程的行编辑器。它有自己的小语言，最常用的就是查找替换：

讲义原文
$ sed -i 's/pattern/replacement/g' file
片段含义
-i直接改文件。不加的话文件不变，只打印结果
s/…/…/sed 里的替换命令。/ 隔开模式和替换内容
g一行里所有匹配都换。不加只换每行第一个

讲师在课程仓库里跑了 sed -i 's/grep/john/g' */*.md。再用 git diff 一看，所有 grep 都成了 john（38:07）。

为什么会在这里踩坑

第一，忘了 g，每行只换掉第一个。第二，-i 改完没法撤销。稳妥的做法是先不加 -i 看输出，确认没错再加。第三，macOS 自带的 sed，-i 后面必须跟一个参数，比如 -i ''。这一条是补充，不在视频里。

glob 归 shell 展开，正则归程序解释 39:17

*.md 这种通配符，shell 会先展开成文件名。正则表达式原样交给程序，由程序自己解释。

bash · 本机实测（目录里有 a/x.md 和 b/y.md）
$ echo */*.md     # shell 先展开成文件列表，echo 只管打印
a/x.md b/y.md
$ echo '*/*.md'   # 加了引号，shell 不展开，原样交给 echo
*/*.md

打个比方glob 像门卫，先按名单把人领进来。程序只看得到名单上的人。正则像一张规则纸条，原样递给屋里的程序自己判断。

glob（通配符）正则表达式
谁来解释shell 在运行程序前展开成路径列表。前提是没加引号程序自己，比如 grep 和 sed
语法很小：* ? {a,b}，还有 [...]复杂得多
用途写路径，/ 有特殊含义匹配任意文本，不懂目录
例子*/*.md：任意子目录里的 .md 文件[^a].*-[0-9]
为什么会在这里踩坑

给 grep 的正则不加引号，里面的 * 会先被 shell 当成 glob。如果正好匹配到文件名，grep 收到的就不是你写的模式。所以正则一律用单引号包起来。

ripgrep（rg） 比 grep 快，也更友好。它默认递归搜当前目录，只是可移植性差一点。

find 逐层检查每个文件，-exec 对结果跑命令 42:57

find 从一个目录往下逐层走。每个文件都拿条件过一遍，全满足的才输出。

讲义例子（注释是笔记加的）
$ find ~/Downloads -type f -name "*.zip" -mtime +30   # 30 天前的 zip 文件
$ find ~ -type f -size +100M -exec ls -lh {} \;       # 大于 100M 的逐个列出
$ find . -name "*.py" -exec grep -l "TODO" {} \;      # 哪些 py 文件里有 TODO

打个比方find 像仓库管理员拿着清单逐层巡查。条件就是清单上的要求。-exec 是让他每找到一件，就顺手贴个标签。

片段含义
-type f只要普通文件。d 表示目录
-name "*.zip"文件名匹配这个 glob。要加引号，交给 find 自己匹配
-mtime +30修改时间在 30 天以前
-size +100M大于 100M
-exec 命令 {} \;对每个结果跑一次命令，{} 换成文件路径。; 表示命令结束。它要写成 \;，否则 shell 会当成分隔符
-maxdepth N最多往下走 N 层，默认不限。讲师现场踩了坑：它要写在 -name 这类条件前面

grep -l 打印匹配的文件名，不打印匹配的行。

为什么会在这里踩坑

-name 后面的 *.zip 不加引号，就会被 shell 先展开。当前目录正好有 zip 文件时，find 收到的就成了具体文件名。另外，把 ls -lh 换成 rm，一行就能批量删文件。讲师也没真跑。你也先用 ls 看清楚再删。

讲师建议

find 的语法很怪，看几个例子学不会。网上的 find 例子极多。所以让 LLM 帮你写 find 命令，效果通常很好（50:00）。更现代的替代品是 fd。

awk 按列取数据 51:07

awk 把每一行按空白切成几列。$1 是第一列，$2 是第二列。

bash · 本机实测
$ printf 'a b c\nd e f\ng h i\n' > m   # 3 行 3 列
$ awk '{print $2}' m                   # 单引号：$2 原样交给 awk
b
e
h
$ awk "{print $2}" m                   # 双引号：$2 先被 shell 换成空串
a b c
d e f
g h i

打个比方awk 像拿着一张 Excel 表，只抄你要的那一列。sed 擅长改文件，awk 擅长拆文件。

  • { … } 里的代码对每一行执行一次。前面可以加一个条件，只处理满足条件的行。练习 17 会用到。
  • 加 -F, 改用逗号分列，awk 马上就能解析 CSV。讲师现场拿没逗号的文件试了一下。没有第 2 列，打印出来全是空行。
为什么会在这里踩坑

awk 程序要用单引号包起来。用了双引号，$2 会先被 shell 当成自己的变量。它通常是空的，awk 收到的就成了 {print }，于是整行原样打印。上面第二条命令就是这样。

流水线的每一级只做一件小事 53:27

前一级的输出就是后一级的输入。几个小工具一连，就能从日志里数出谁被乱试得最多。

讲义原文（讲师的服务器现场没连上，讲义给出了结果）
$ ssh myserver 'journalctl -u sshd -b-1 | grep "Disconnected from"' \
  | sed -E 's/.*Disconnected from .* user (.*) [^ ]+ port.*/\1/' \
  | sort | uniq -c \
  | sort -nk1,1 | tail -n10 \
  | awk '{print $2}' | paste -sd,
postgres,mysql,oracle,dell,ubuntu,inspur,test,admin,user,root

打个比方像工厂流水线。每个工位只拧一颗螺丝，整条线连起来就能出成品。

片段作用（视频 54:00 到 56:21）

grep "Disconnected from"有人登录失败或断开时，日志里会出现这句

管道把程序接到程序，重定向把流接到文件 58:43

| 把左边程序的标准输出，接到右边程序的标准输入。> 和 < 把流改接到文件上。

bash · 本机实测

ls: cannot access '/nonexistent': No such file or directory
$ printf '3\n1\n2\n' > f; sort f > f; wc -c < f   # > 先把 f 清空，sort 读到的是空文件

打个比方每个程序都接着三根水管。0 号进水，1 号出水，2 号排污。管道把一根出水管接到下一个程序的进水口。重定向把水管接进水桶。

大多数命令行程序没拿到文件参数，就去读 stdin。管道正是靠这一点才能用。

写法效果

if 看的是退出码，不是真假值 1:01:02

bash 的 if 后面跟的是一条命令。命令退出码是 0 就算真，非 0 就算假。

bash · 本机实测
$ grep -q zzz data; echo $?   # 没找到 zzz，退出码是 1
1
$ if grep -q 31 data; then echo found; else echo missing; fi   # if 直接看 grep 的退出码
found
$ a=x; [ "$a"="y" ] && echo same   # = 两边没空格，成了一个非空字符串，永远为真
same
$ a=x; ["$a" = "y"]                # [ 后面没空格，shell 去找叫 [x 的程序
bash: [x: command not found

打个比方if 不问“这句话对不对”，只问“这件事办成没有”。办成了返回 0，就走 then。这和 C 语言里 0 为假正好相反。

bash 有变量、条件、循环和函数。你在提示符里敲的，就是一小段被解释执行的代码。

bash · 语法骨架（讲义，注释是笔记加的）
if command1; then command2; command3; fi      # command1 退出码为 0 才走 then
while command1; do command2; command3; done   # command1 一直成功，就一直循环
for varname in a b c d; do command; done      # 依次把 a b c d 放进 varname
for i in $(seq 1 10); do …; done              # $( ) 是命令替换，把输出塞进来
概念说明
退出码程序结束时返回的一个数。$? 存着上一条命令的退出码。grep 找到返回 0，没找到返回 1，出错返回 2
$(cmd)命令替换。先运行 cmd，用它的输出换掉整个 $( )，再按空白切词。旧代码里的反引号作用一样。$( ) 能嵌套，优先用它
test / [专门做比较的程序，条件成立就返回 0。[ -f file ] 判断文件存在。[ "$var" = "string" ] 判断字符串相等
[[ ]]bash 内建的加强版，引号相关的怪问题更少
sleep 10视频里放进 while 循环，每 10 秒检查一次
为什么会在这里踩坑

[ 其实是一个命令，] 是它的最后一个参数。所以 [、] 和 = 两边都要有空格。少了空格不一定报错，可能悄悄地永远为真。上面第三条就是。

脚本要过两关：执行权限和第一行的 #! 1:08:12

运行 ./lecture.sh 时，系统先查有没有执行权限。再读第一行的 #!，决定把文件交给哪个解释器。

bash · 本机实测
$ printf '#!/bin/sh\necho hi\n' > lecture.sh   # 第一行 #! 指定用 /bin/sh 来跑
$ chmod +x lecture.sh   # 加执行权限，Linux 下不加会 Permission denied
$ ./lecture.sh          # 带 ./，明说文件就在当前目录
hi
$ lecture.sh            # 不带 /，只查 PATH，当前目录不在里面
bash: lecture.sh: command not found

打个比方#! 像快递单上的收件人。系统看一眼第一行，就知道这个包裹该交给谁拆。执行权限是门禁卡，没卡连门都进不去。

命令长到三行，在提示符里就很难改了。把它们写进文件，bash 会从上到下逐行执行。效果和你一行行敲一样。

  • shebang #!/path：写在文件第一行，指定用哪个程序运行它。./lecture.sh 就相当于 /bin/sh lecture.sh。换成 #!/usr/bin/python 就能直接跑 Python。R、Julia、Ruby 都行。Java 不行，它得先编译。
  • 执行权限：ls -l 左边的 rwx 分别是读、写、执行。新建的文件没有 x，执行会报 Permission denied。chmod +x 加上执行位后，ls 还会把它换个颜色显示。
  • 为什么要写 ./：名字里没有 / 时，shell 只查 PATH。当前目录故意不放进 PATH。不然有人在目录里放个 ls 文件，你敲的 ls 就被顶替了。
本机实测差异：Git Bash 不认 chmod

在 Windows 的 Git Bash 里，以 #! 开头的文件，ls -l 直接显示 -rwxr-xr-x。不用 chmod 也能运行。不带 ./ 运行一样会报错：

bash · 本机实测
$ ls -l lecture.sh
-rwxr-xr-x 1 lrhto 197610 30 Oct 29 15:29 lecture.sh
$ lecture.sh
bash: lecture.sh: command not found

想亲眼看到 Permission denied，请在 WSL 或 Linux 里做练习 9。

讲义的完整脚本：一直跑，跑到失败为止 1:08:44

这个脚本循环跑测试，直到某一次失败才停。日志文件里留下的，正好是失败那一轮。

打个比方像设个闹钟让机器一直试。你去喝咖啡，它摔倒的那一刻就停下。现场原样留着，等你回来看。

讲师在 6.824 分布式系统课上碰到一个测试。它跑一百次才挂一次。于是写了这个脚本。后台先把 CPU 压满，再循环跑测试，人去喝咖啡。

flaky.sh（讲义脚本，注释译成中文并补了考点）
#!/bin/bash
set -euo pipefail                   # 三个安全开关，下面的表格逐个讲

# 在后台启动 CPU 压力
stress --cpu 8 &                    # & 放到后台，shell 不等它
STRESS_PID=$!                       # $! 是刚才那个后台进程的 PID

# 准备日志文件
LOGFILE="test_runs_$(date +%s).log" # 用时间戳起名，每次都不重名
echo "Logging to $LOGFILE"

# 一直跑测试，直到失败
RUN=1                               # 从 1 开始，正好避开 ((RUN++)) 的坑
while cargo test my_test > "$LOGFILE" 2>&1; do   # 每轮覆盖写，最后留下失败那轮
    echo "Run $RUN passed"
    ((RUN++))
done

# 收尾并报告
kill $STRESS_PID                    # 别忘了关掉后台的压力进程
echo "Test failed on run $RUN"
echo "Last 20 lines of output:"
tail -n 20 "$LOGFILE"
echo "Full log: $LOGFILE"
新东西含义
&放到后台运行，shell 不等它结束。$! 是这个后台进程的 PID
$(date +%s)当前的 Unix 时间戳，本机实测的一个例子是 1793288178。每次日志名都不一样
> "$LOGFILE" 2>&1每一轮的全部输出都覆盖写进日志。循环结束时，文件里正好是失败那一轮
((RUN++))算术展开，RUN 加 1
set -e任何命令失败，脚本立刻退出
set -u用到没定义的变量就报错，不当成空串
set -o pipefail管道里任一程序失败，整条管道就算失败

下面的演示逐行执行这个脚本。右侧同步显示变量、日志文件和输出。失败轮次和 PID 都是示意。

bash · 本机实测：三个开关的效果
$ bash -c 'set -u; echo "$NOPE"'   # -u：变量没定义，直接报错
bash: line 1: NOPE: unbound variable
$ bash -c 'set -e; false; echo never'; echo "exit=$?"   # -e：false 一失败就退出
exit=1
$ bash -c 'false | true; echo $?'   # 默认只看管道里最后一个程序
0
$ bash -c 'set -o pipefail; false | true; echo $?'   # pipefail：任一失败就算失败
1
为什么会在这里踩坑（补充，非视频内容）

算术命令 ((表达式)) 的值为 0 时，退出码是 1。讲义脚本里 RUN 从 1 开始，所以没事。要是从 0 开始，第一次 ((RUN++)) 的值就是 0。退出码成了 1，set -e 会让脚本一声不吭地退出。本机实测：

bash · 本机实测
$ bash -c 'set -e; RUN=0; ((RUN++)); echo "after RUN=$RUN"'; echo "exit=$?"   # echo 那句根本没跑到
exit=1

改成 RUN=$((RUN + 1)) 就没这个问题。
