上一讲说过，shell 是一门完整的编程语言。它和普通语言不一样。它的设计只围着两件事转。一是运行程序，二是让程序之间高效通信。这套设计高度依赖约定（conventions）。一个 CLI 程序想和别人配合好，就得守这些约定。

  • true 总是成功，false 总是失败。它们都是程序。

按下 Ctrl+C，前台进程会收到 SIGINT 信号。程序没处理它，就按默认动作退出。程序处理了它，就可以不退。

bash · 本机实测
$ bash -c 'trap "echo got INT, not stopping" INT; kill -INT $$; echo still alive'   # 给自己发 SIGINT，trap 接住后接着跑
got INT, not stopping
still alive

打个比方信号像有人拍你肩膀。你可以停下手里的活应付一下，再接着干。SIGKILL 不是拍肩膀，是直接把你拖走。

信号（signal）是一种特殊的进程间通信，也叫软件中断。进程收到信号，先暂停手头的事去处理它。处理完，执行路线可能就变了。

程序可以自己处理信号。讲义的 Python 程序捕获 SIGINT 后，只打印一句话，并不退出。想停它，得用更凶的 SIGQUIT，按键是 Ctrl+\（27:21）：

sigint.py（讲义原文）
#!/usr/bin/env python
import signal, time

def handler(signum, time):
    print("\nI got a SIGINT, but I am not stopping")

signal.signal(signal.SIGINT, handler)
i = 0
while True:
    time.sleep(.1)
    print("\r{}".format(i), end="")
    i += 1

I got a SIGINT, but I am not stopping

本机实测差异：Windows 原生 Python 收不到 Git Bash 的 kill -INT

在 Git Bash 里，对后台的 python sigint.py 执行 kill -INT。处理器没有被调用，kill -QUIT 也杀不掉它。原因是 Git Bash 的信号由 MSYS 运行时模拟，只对 MSYS 程序有效。Windows 原生的 python.exe 收不到。于是笔记用 bash 的 trap 把同样的逻辑重写成 sigint.sh，在本机真跑：

sigint.sh（本笔记改写的 bash 版）
#!/usr/bin/env bash
trap 'echo; echo "I got a SIGINT, but I am not stopping"' INT
i=0
while true; do
    sleep 0.1
    printf '\r%d' "$i"
    i=$((i + 1))
done

先用 set -m 打开作业控制，让脚本在后台跑。两次 kill -INT 之后，再发 kill -TERM：

注意最后用的是 SIGTERM，不是 SIGQUIT。bash 手册写明，它在任何情况下都忽略 SIGQUIT。这条是补充，非视频内容。退出码 143 等于 128 加 15，15 是 SIGTERM 的编号。手推过程见第 6 节的演示。

trap 兜得住 TERM，兜不住 KILL 27:59

内建命令 trap 给信号挂一个处理函数。脚本被 Ctrl+C 或 kill 打断时，也能先把临时文件删掉。但 SIGKILL 谁也接不住。

讲义脚本（注释译成中文）
#!/usr/bin/env bash
cleanup() {
    echo "Cleaning up temporary files..."
    rm -f /tmp/mytemp.*
}
trap cleanup EXIT  # 脚本退出时运行 cleanup
trap cleanup SIGINT SIGTERM  # 按 Ctrl-C 或被 kill 时也运行

打个比方trap 像在门口贴一张“离开前关灯”。正常下班、被人叫走，都会看到它。SIGKILL 是直接断电，提示贴了也没人看。

Ctrl-Z 是暂停，不是退出 28:42

按 Ctrl+Z，进程收到 SIGTSTP 被挂起，但还活着。之后用 fg 放回前台，或用 bg 放到后台接着跑。

打个比方Ctrl+Z 像视频的暂停键，不是关掉播放器。fg 是回到大屏接着放。bg 是缩成小窗，在角落里接着放。

私钥等于密码，只有公钥能给别人 31:59

SSH 用一对密钥证明你是你。私钥留在自己电脑上，公钥放进服务器的 ~/.ssh/authorized_keys。登录时只证明你有私钥，私钥本身不出门。

bash · 最小例子（示意）

ssh-copy-id -i .ssh/id_ed25519 alice@remote          # 只是把公钥追加进对方的 authorized_keys
ssh alice@remote                                     # 之后改用密钥登录，不用再输服务器密码

打个比方公钥像锁芯，可以随便装到别人家的门上。私钥是唯一那把钥匙，丢了谁都能开门。口令是给钥匙再套一个密码盒。

程序员越来越多地在远程服务器上干活。最常用的工具是 SSH，全称 Secure Shell。它在远端给你一个熟悉的 shell：

讲义原文
$ ssh alice@server.mit.edu

这条命令以用户 alice 登录 server.mit.edu。讲师演示时写的是 IP 地址。server.mit.edu 这种名字，最后也会被 DNS 翻译成一个 IP（32:09）。默认每次都要输密码，很烦。所以要用 SSH 密钥。

  • 公钥密码学：一对私钥加公钥。客户端能向服务器证明“我有私钥”，却不泄露私钥。密钥认证更方便，也更安全，应该优先用。
  • 私钥常见的是 ~/.ssh/id_rsa，较新的是 ~/.ssh/id_ed25519。它等同于你的密码。永远不要分享，也别复制粘贴到任何地方。讲师现场展示，是因为那是临时密钥。公钥是 .pub 文件，可以给别人。GitHub 就用它来验证你。
  • 生成用 ssh-keygen -a 100 -t ed25519 -f ~/.ssh/id_ed25519。想检查有没有口令、顺便验证私钥，用 ssh-keygen -y -f /path/to/key。
  • 服务器查 ~/.ssh/authorized_keys，决定放谁进来。把公钥拷过去，用 ssh-copy-id -i .ssh/id_ed25519 alice@remote。也可以手动写 cat .ssh/id_ed25519.pub | ssh alice@remote 'cat >> ~/.ssh/authorized_keys'。讲师强调，ssh-copy-id 这个“魔法命令”只做一件事。它把一行字符串追加到 authorized_keys 里（34:43）。

引号决定管道在哪台机器上跑 35:19

ssh 后面跟命令，就在远端执行，再把输出传回本地。没加引号时，| 由本地 shell 切开。加了引号，整串交给远端的 shell 去解析。

讲义原文（注释译成中文）
# 这里 ls 在远端跑，wc 在本地跑
ssh alice@server ls | wc -l

# 这里 ls 和 wc 都在服务器上跑
ssh alice@server 'ls | wc -l'

打个比方不加引号，像打电话让同事把文件名一个个念给你。你自己在这边数。加了引号，像让同事数完，只报一个数字给你。

ssh 有个常被忽略的功能。它能非交互地执行命令，还能正确处理 stdin 和 stdout。所以它能和别的命令组合。讲师说，SSH 不是魔法命令。它和几乎所有命令一样，接收输入，产生输出。

区别全在引号。没引号时，本地 shell 先把整行按 | 切开，wc -l 归本地。加了引号，'ls | wc -l' 整体成为一个参数交给 ssh。到了远端，再由远端的 shell 去解析。本节末尾的演示画了这两条数据路径。

export 只管这次会话，长期生效要写进 .bashrc 43:28

export PATH=… 只对当前会话和它的子进程有效，关掉终端就没了。写进 ~/.bashrc，每个新开的交互式 bash 都会重新执行一遍。

打个比方export 像在白板上写字，散会就擦了。写进 .bashrc，像写进每次开会必念的开场白。

上一讲讲过，PATH 是一串放程序的目录。想加一个目录，就是普通的变量赋值。而且要 export，不然子进程看不到。

问题是，export 只对这个会话和它的子进程有效。断开重连就没了（45:45）。要长期生效，就写进 shell 的配置文件。下面在干净环境里实测：
