原题：写一个正则，用 grep 在你的代码里找出 subprocess.Popen(..., shell=True)。然后试着“打破”这个正则。那些让 grep 失手的危险代码，semgrep 还能匹配上吗？

字符级搜索会漏报，也会误报。semgrep 按语法树匹配，准得多，但也有盲区。

semgrep 见第 9 讲第 4 节。正则里的转义 \. 和 \(，见第 9 讲第 13 节。

▶跑：两版 grep

第一版命中 5 行，其中只有 1、2 是真调用。文档字符串、注释 8、字符串 9 都是误报。3 跨行、4 有空格、5 是别名、6 藏在字典里，全漏了。

考点（答案写在注释里）

# 也可以靠 ruff 的 S602、S604 这类规则，再加代码评审
# 或者约定“禁止把 **kwargs 传给 subprocess”
# 没有一种静态分析是完美的，几层叠加更可靠（补充，未实测）

练习 5 · 只换行首的项目符号，用 ^ 把位置锚住

Git Bash 实测（sed + Vim）

原题：在你的 IDE 或编辑器里练习正则搜索替换。把这份讲义里的 - Markdown 项目符号换成 *。注意，直接替换所有 “-” 是错的。文件里很多 “-” 并不是项目符号。

模式写成 ^( *)- ，只认行首、缩进之后的那个 - 加空格。正好 28 行被改，和项目符号的行数一致。

K先回顾

^ 行首、捕获组与 \1，见第 9 讲第 14 节。还会用到第 1 讲的 sed、diff 和 grep -c。

实测改动

实测没有联网下载。用的是讲义源文件 code-quality.md 的本地副本。它正是题目链接的那个文件。准备步骤把它复制进沙箱。这份副本在生成笔记后已删除。

▶跑：先数一数
!为什么会在这里踩坑：把所有 - 都换掉
现象
68 行被改。YAML 头的 --- 变成了 ***，日期变成 2026*01*23。high-quality、regular-expressions 这样的连字符和锚点，也全坏了。上面列出的，是非项目符号的受害行。
▶跑：只换行首的项目符号

模式 ^( *)- 拆开看。行首，可选的缩进，一个 -，一个空格。缩进被捕获为 \1，替换时原样放回。正好 28 行被改，和项目符号的行数一致。

▶跑：在编辑器里做同样的事（Vim）

Vim 方言里，分组要写成 \( 和 \)，\s 是空白字符。-Es 让 Vim 以无界面的 Ex 模式执行命令。结果和 sed 逐字节相同，用 cmp 验证过。

在 VS Code 里也能做。打开查找替换，点亮 .* 按钮。查找 ^(\s*)- ，替换为 $1* 。

打个比方像只把每段开头的小圆点换成星号。正文里的连字符，一个都不碰。^ 就是告诉工具，只看行首。

考点（答案写在注释里）
sed -E 's/^( *)- /\1* /'   # 对：缩进捕获下来，替换时原样放回
sed 's/^- /* /'            # 缩进的子列表项，它的 - 不在行首，会漏掉
sed 's/^\s*- /* /'         # 缩进被一起吃掉又没放回，子列表被“拍平”到第一层
# 这份讲义恰好没有缩进的 - 项目符号，所以三种写法都改 28 行（推理，未实测）
# 可练习 6 的子题前面带缩进，说明文件里确实有嵌套列表。捕获缩进更稳妥

练习 6 · 正则取名字会吃过头，JSON 还是交给解析器

Git Bash 实测

原题：写一个正则，从形如 {"name": "Alyssa P. Hacker", "college": "MIT"} 的 JSON 里捕获名字。本例是 Alyssa P. Hacker。提示：第一次尝试可能会得到 Alyssa P. Hacker", "college": "MIT。读 Python 正则文档里讲贪婪量词的部分，来修正它。6.1 让模式在名字含有 " 时也能工作。JSON 里双引号转义成 \"。6.2 实践中不推荐用正则做复杂解析。用你的语言自带的 JSON 解析器，写一个命令行程序。它从 stdin 读这种 JSON，把名字输出到 stdout。Python 里除了 import json，只需一行。

(.*) 贪婪，会一直吃到最后一个引号。换成 [^"]* 就停在下一个引号。要处理转义，就让 \\. 成对吃。真遇到复杂 JSON，交给解析器。

!为什么会在这里踩坑：JSON 换个写法，正则就失灵
现象
键的顺序换了，冒号后面没有空格。这都是合法 JSON，grep 却一个都没匹配到，退出码 1。
原因
正则依赖表面写法。"name": " 里那个空格就是硬性要求。JSON 的语法有嵌套、转义和任意空白。这些超出了正则擅长的范围。
正确写法
用解析器。name.py 照样输出 Alyssa P. Hacker。讲义也说，不推荐用正则解决复杂的解析问题。
考点（答案写在注释里）
"name": "((?:[^"\\]|\\.)*)"   # 转义感知：每步吃一个普通字符，或者吃“反斜杠加任意字符”这一对
# 为什么要写 [^"\\]，不能只写 [^"]
# [^"] 允许单独吃掉反斜杠。遇到 \" 时，它可能先吃掉 \
# 下一步再把 " 当成结束引号，又回到被截断的结果
# 把反斜杠排除在外，它只能走 \\. 这条分支，和后面的字符成对被吃掉
