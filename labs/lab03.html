练习 1 · 处处开 Vim 模式，shell 里一行 set -o vi 就行

讲义 · Exercises · 1Git Bash 实测（shell 部分）图形软件未实测

原题：在所有支持 Vim 模式的软件里开启它，比如编辑器和 shell。接下来一个月，所有文本编辑都用 Vim 模式。觉得某个操作效率低时，你会想“一定有更好的办法”。那就去 Google 一下，多半真的有。

交互式 bash 默认是 emacs 键位。就是 Ctrl-A 到行首、Ctrl-E 到行尾那一套。set -o vi 之后换成 vi 键位。这时按 Esc 进入命令模式。可以用 b、w、0、$、dw、ciw 编辑命令行。

用 inputrc 开启时，提示符前多了 (ins)，表示当前在插入模式。按 Esc 后会变成 (cmd)。本页的命令是批量喂进去的，所以看不到切换。

打个比方Vim 键位像一门外语。只在一个软件里用，就像只在课堂上说外语。处处都开，才是把自己扔进语言环境。

!为什么会在这里踩坑：set -o vi 一关终端就没了
误解
在终端里敲了 set -o vi，以为从此都是 Vim 键位。
实际
它只改当前这个 shell。新开一个终端，又回到默认的 emacs 键位。上面 ex01-a 里，改之前显示的就是 emacs on。
正确写法
写进 ~/.bashrc，只管 bash。写进 ~/.inputrc，所有用 readline 的程序都生效。
补充（非讲义内容）：一个月怎么算练成
  • 第 1 周：不看表也能做到这些。i、a、o 进插入，Esc 回来。hjkl、w、b、e 移动。dw、cw、u 编辑。
  • 第 2 到 3 周：开始自然地用计数 3w 和行内查找 f(。还有文本对象，比如 ci" 和 da(。
  • 第 4 周：遇到重复操作会停下来。想想有没有更短的按法，并真的去查。这就是讲师说的那种“懒”。

阶段划分是笔记作者给的参考。你的体验以实际为准。

!为什么会在这里踩坑：同样 2 键，4j 和 6G 不一样
错误写法
用 4j 从第 2 行下到第 6 行，也是 2 键。
现象
diff 显示第 6 行变成了 print("fizz", end="buzz")，结果 FAIL。
原因
j 会尽量保持列号。上一步光标在第 2 行 C31，到第 6 行还是 C31。那里正好在 end="" 那对空引号里。ci" 改的是光标所在的，或者后面最近的那对引号。6G 和 :6<CR> 会把光标放在第一个非空字符上。后面第一对引号才是 "fizz"。
教训
高尔夫解法要算上光标的隐含状态。比如列号、寄存器和上次搜索。这也是回放器每次都从同一个干净状态开始的原因。

$ bash check.sh colon.keys                    # 第一行还是 Ex 模式顺手打出的第 6 行

!为什么会在这里踩坑：写客户端时遇到的两个坑
现象
第一版客户端发完 didOpen 就一直等诊断，偶尔卡住不动。
原因
gopls 会反过来向客户端发请求。比如 workspace/configuration，问你的设置是什么。客户端不回复，它可能一直等。第 45 到 47 行对这类请求一律回复“没有设置”。真正的编辑器当然会认真回答。这就是“配置语言服务器”在协议层面的样子。
另一个坑
行列号在 LSP 里从 0 开始，人习惯从 1 开始。第 64 到 65 行的 at() 专门做这个转换。打印时再加回 1。差一位，就会在错误的位置请求补全。结果莫名其妙。
考点（答案写在注释里）
textDocument/completion   # 请求：带 id，服务器用同一个 id 回复
textDocument/didOpen      # 通知：没有 id，服务器不回复
publishDiagnostics        # 服务器主动推送：文件一打开、一修改，它就重新分析
# 为什么是推送：错误随内容变，编辑器不用轮询，红波浪线跟着打字更新
workspace/configuration   # 服务器反过来问客户端。不回复，它可能一直等

!为什么会在这里踩坑：目录少了一层，插件不加载
错误写法
把 hello.vim 直接放进 pack/demo/start/。没有插件自己的目录，也没有 plugin/。
现象

原因
Vim 只把 start/ 下的每个子目录当成一个插件。再执行它里面 plugin/ 下的脚本。直接放在 start/ 下的文件，不会被执行。
正确写法
放成 pack/demo/start/hello/plugin/hello.vim。git clone 一个插件仓库到 start/ 下，正好就是这个结构。
