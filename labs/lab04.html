!为什么会在这里踩坑：各 time 一次就下结论
误区
各 time 一次就下结论。
实际
同一条 grep 命令跑 20 次，最快 104 ms，最慢 255 ms。差了两倍多。第一次运行还可能特别慢，因为文件还不在磁盘缓存里。所以要预热，也就是 --warmup。
正确做法
预热，多次重复，报告均值 ± σ。比较两个命令前，先确认它们输出相同。尽量在安静的机器上测。

性能 4 · 3 个进程挤 2 个核，合计最多 200%

taskset / stress / htop 未实测start /affinity 实测

原题：运行一个占用大量资源的程序，同时用 htop 监视系统。试着用 taskset 限制进程能用的 CPU：taskset --cpu-list 0,2 stress -c 3。为什么 stress 用不满三个 CPU？

不是 stress 不想用，是只给了它两个 CPU。进程被限制在哪些核上，最多就只能拿到那么多 CPU 时间。

K先回顾

资源监控见第 4 讲第 12 节。CPU 时间除以墙钟时间，见第 10 节。

▶跑：题目要求的 Linux 版
?原理

stress -c 3 启动 3 个忙等的工作进程，各自都想吃满一个核。taskset --cpu-list 0,2 只允许它们在 CPU 0 和 CPU 2 上运行。3 个进程挤 2 个核，调度器只能让它们轮流跑。两个核满载，每个 stress 进程平均约 2/3 个核。答案是：不是 stress 不想用，是只给了它两个 CPU。

Windows 上对应的工具是 start /affinity 掩码。掩码 5 是二进制 0101，也就是 CPU 0 和 CPU 2。子进程会继承这个掩码。用一个 Python 脚本代替 stress：

▶跑：只允许 CPU 0 和 CPU 2

输出怎么读：不限制时，三个 worker 各拿到 80% 多。没到 100%，是因为机器上还有别的负载。限制后合计只有 121%，远不到 300%。也没到理论上限 200%。这两个核上还有其他程序在抢。数字每次运行都会变，但“合计不超过 200%”不会变。

性能 5 · netstat 找到 PID，Git Bash 里要用 kill -W

ss 未实测netstat 实测

原题：常见问题是，想监听的端口已经被别的进程占了。先运行 python -m http.server 4444，在 4444 端口起一个最小的 web 服务器。在另一个终端里运行 ss -tlnp | grep 4444 找到这个进程。再用 kill <PID> 结束它。

Linux 上用 ss -tlnp 查端口对应的 PID，再 kill。本机用 netstat 查。Git Bash 内建的 kill 不认 Windows PID，要换 /bin/kill -W。

K先回顾

资源监控里的 ss 和 lsof，见第 4 讲第 12 节。信号与 kill 见第 2 讲。

▶跑：题目要求的 Linux 版

ss -tlnp 里，-t 只看 TCP，-l 只看监听。-n 不解析名字，-p 显示进程。看别人的进程要 sudo。

{}本机版：用 netstat 找 PID
▶跑

输出怎么读：netstat 那一行的最后一列是 PID。tasklist 确认它是 python.exe。第一次 kill $PID 失败了，报 No such process。换成 /bin/kill -W 才成功。最后再查一次，端口已经空闲。脚本的 teardown 还会再检查一遍，确保没有残留的服务器。

打个比方端口像一个门牌号。netstat 是物业的登记簿，查得到谁住在 4444 号。可 Git Bash 的 kill 拿的是另一本花名册。同一个人，在两本册子上编号不同。

!为什么会在这里踩坑：Git Bash 的 kill 不认 Windows PID
错误写法
kill 21200，PID 来自 netstat
真实报错
kill: (21200) - No such process，见上面 p5-a 的输出
原因
bash 内建的 kill 用的是 Git Bash（MSYS）自己的进程号。netstat 和 tasklist 给的是 Windows 进程号。两者不是一回事。
正确写法
/bin/kill -W PID，-W 表示 Windows PID。或者用 taskkill //PID PID。
!为什么会在这里踩坑：端口冲突在 Windows 上可能不报错
现象
同一个端口起第二个 http.server，没有报 Address already in use。netstat 里出现两行 LISTENING。
原因
Python 的 HTTPServer 默认开着 SO_REUSEADDR，也就是 allow_reuse_address = True。这个选项在 Windows 上比 Linux 宽松。它允许另一个套接字绑定到同一端口。在 Linux 上，第二个服务器会直接报 OSError: [Errno 98] Address already in use。这一条是补充，未实测。
启示
排查端口冲突时，别只靠报错。直接查 netstat 或 ss，看有几个进程在监听。
考点（答案写在注释里）
python -m http.server 4444 --bind 127.0.0.1   # 只接受本机连接，做实验更安全
# 默认的 0.0.0.0 会在所有网卡上监听
# 局域网里的其他机器，也能访问你当前目录的文件
