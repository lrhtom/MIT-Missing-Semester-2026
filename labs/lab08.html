练习 1 · 好注释删掉了，后人就得重踩一遍坑

Git Bash 实测改用 CPython 源码

原题：浏览一个知名项目的源码，比如 Redis 或 curl。找出讲座提到的几类注释。比如有用的 TODO，对外部文档的引用。还有讲“为什么不用显而易见做法”的注释。以及来之不易的教训。如果这条注释不在了，会失去什么？

好注释交代的，是代码里看不出的东西。比如现状、原因、出处，以及和原文的差异。删掉它，后来者要么把对的改错，要么重做一遍实验。

K先回顾

七类值得写的注释，见第 8 讲第 2 节。grep -n -A/-B 显示行号和上下文，见第 1 讲。

?原理：怎么找

注释有固定的“记号”，可以 grep。TODO、XXX、FIXME 最常见。引用常带 Reference、RFC、See，或者作者名、论文名。教训常带 issue 编号，CPython 里是 bpo- 和 GH-。why-not 常出现 instead of、avoid、don't，或者 could … but。先 grep 出候选，再带上下文读。

▶跑：带上下文的 TODO（smtplib.py）

输出怎么读。TODO 之前的 5 行解释了现状和原因。有多个 Resent 块时，没法确定哪个最新。所以宁可抛 ValueError，也不去猜。TODO 本身说了要做什么：加启发式，让用户选择开启。还说了为什么值得做：几乎总能猜对。

删掉它，后来者可能把 ValueError 当成 bug“修”掉。或者重新论证一遍能不能猜。

▶跑：引用外部文献，并注明和原文的差异（random.py）

第 540 行给出完整的论文出处。读者可以对照原文验证算法。第 863 行更值钱：原论文漏了一个 log(v)。这正是讲义说的“注明和参考资料的差异”。

没有它，下一个对照论文的人会以为代码写错了。他会把正确的代码，“改”成论文里的错误版本。

▶跑：why-not 与 issue 编号（heapq.py、_pyio.py）

heapq 这段是教科书式的 why-not。它说我们本可以提前跳出循环。但事实证明这不是好主意，尽管很多书都这样写。接着给了原因。弹出时被筛进来的元素通常很大，提前比较往往不划算。最后给了出处：Knuth 卷 3。

GH-95782 则把一行看似多余的 max(…, 0)，和一个 issue 关联起来。这是“来之不易的教训”的常见写法。删掉注释，有人会觉得 max 多此一举。

输出怎么读。调用者传进来的，可能是可变的 bytearray。s = s + … 会生成新对象，调用者的数据不变。s += … 对 bytearray 是就地追加，会悄悄改掉调用者的缓冲区。真正的 b32encode 处理完，缓冲区仍是 abc。

!为什么会在这里踩坑：隔离了配置就没有身份
现象
Committer identity unknown … fatal: no email was given and auto-detection is disabled，退出码 128。
原因
为了不碰你的真实配置，这里让 git 不读全局配置。于是它不知道“你是谁”。amend 会保留原作者，但提交者换成了当前用户。提交者必须有名字和邮箱。user.useConfigOnly=true 让 git 不去猜身份。
补充
不加这个选项会怎样？git 会用“系统用户名@主机名”拼一个邮箱。本机拼出来的不合法，所以同样报错。在主机名完整的系统上，它可能“成功”。你的主机名就被悄悄写进了提交。
正确写法
先在这个仓库里设身份：git config user.name … 和 git config user.email …。不加 --global，就只影响当前仓库。见上面的 ex02-amend。
误区
想用 --amend 去改 7809933 那条 fix。
实际
amend 只能改分支最末端的提交。改更早的要用交互式 rebase，这是补充。而且它会重写之后所有提交的哈希。已经推送、别人在用的历史，不该这样改。所以提交信息要在提交时就写好。

打个比方提问像问路。“火车站怎么走”只能换来一大段描述。“前面路口左转是火车站吗”，对方点个头你就走了。

!为什么会在这里踩坑：多追问一步就能发现
错误写法
… LEFT JOIN labs l ON s.id = l.student_id WHERE l.lab = 'lab01'
现象
看上面 ex07-b 最后一行。ben 又消失了，结果和普通 JOIN 一样。
原因
WHERE 在连接之后才过滤。ben 那行的 l.lab 是 NULL。NULL = 'lab01' 不为真，于是被滤掉了。这条是补充的 SQL 语义。
正确写法
把对右表的条件写进 ON：ON s.id = l.student_id AND l.lab = 'lab01'。这就是“别接受不完整的答案”的价值。多问一个是非题，就多学到一个坑。
