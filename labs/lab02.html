练习 1 · -- 之后的参数，一律不当选项

讲义 · Arguments and Globs · 1Git Bash 实测

原题：你可能见过 cmd --flag -- --notaflag 这样的命令。-- 是个特殊参数，告诉程序停止解析选项。它之后的一切，都当作位置参数。这有什么用？试试 touch -- -myfile，然后不用 -- 删掉它。

答案是 rm ./-myfile。加个路径前缀，文件名就不以 - 开头了。程序不会再把它当选项。

K先回顾

参数只是字符串，flag 是程序自己解析的约定。见第 2 讲第 2 节。glob 在程序运行前展开，见第 3 节。

?原理

程序从左到右看参数。以 - 开头的当选项，其余当文件名。文件名本身以 - 开头时，就分不清了。-- 是绝大多数程序都认的约定，getopt 系列解析库都支持。它之后的参数一律不当选项。另一个办法是给文件名加路径前缀，写成 ./-myfile。这样它就不以 - 开头了。

▶跑

读输出：rm -myfile 被当成了选项 -m -y …。GNU rm 报 unknown option，还贴心地提示 rm ./-myfile。加上 -- 之后 exit=0。最后 ls | wc -l 为 0，说明文件确实删掉了。题目要求“不用 -- 删掉”，答案就是 rm ./-myfile。

打个比方-- 像检票口喊一声“后面的都是乘客”。之后哪怕有人举着“司机”的牌子，也只当他是乘客。

!为什么会在这里踩坑：glob 展开出一个“选项”

-- 真正保命的是这种场景。目录里恰好有个叫 -l 的文件。

现象
ls * 输出的是 a.txt 和 b.txt 的长格式。文件 -l 却不见了。
原因
shell 把 * 展开成 -l a.txt b.txt，按字母序 - 排在前面。ls 收到的就是 ls -l a.txt b.txt。换成 rm *，目录里又有个叫 -rf 的文件，后果可想而知。
正确写法
ls -- * 或 rm ./*。这样 -l 就被当作文件名列了出来。

搜索内容以 - 开头时，道理一样：

grep -v notes.txt 把 -v 当成了反向匹配选项。notes.txt 成了模式，grep 转去读 stdin。这里 stdin 是空的，于是返回 1。grep -- -v notes.txt 才是在 notes.txt 里找 -v。

考点（答案写在注释里）
cmd --flag -- --notaflag   # --notaflag 只是普通位置参数，不会被当成选项
                           # -- 本身被解析库吃掉，不出现在位置参数里
rm ./-myfile               # 不用 -- 也能删：加个路径前缀
grep -- -v notes.txt       # 在文件里搜 -v，而不是打开反向匹配

练习 3 · printenv 看子进程的环境，export 看 shell 的记录

讲义 · Arguments and Globs · 3Git Bash 实测

原题：进程替换 <(command) 让你把命令输出当文件用。用 diff 加进程替换，比较 printenv 和 export 的输出。为什么不一样？提示：diff <(printenv | sort) <(export | sort)。

环境变量是进程的一个属性。printenv 看的是子进程收到的环境。export 看的是 shell 自己记的导出表。

K先回顾

进程替换和环境变量，见第 2 讲第 5 节，有演示。

实测改动

直接在你的 shell 里跑，会把整个环境打出来。里面有 PATH、用户名和各种令牌。为了不把本机环境写进页面，先用 env -i 清空环境。只给 HOME 和 PATH，再启动一个干净的 bash 做比较。命令本身不变。

▶跑

读输出时，< 是 printenv 的行，> 是 export 的行：

  • 格式不同：printenv 打印 NAME=value。export 不带参数时，打印能被 shell 重新读入的 declare -x NAME="value"。所以每一行都“不同”。
  • 只在 export 里：EMPTY。它被标成导出，但从没赋值。shell 记得这个标记，可它不会进入子进程的环境。printenv 自然看不到。
  • 只在 printenv 里：_=/usr/bin/printenv。bash 启动每个子进程前，会把 $_ 设成该程序的路径。再把它放进那个子进程的环境。shell 自己的导出表里没有这一项。
  • 两边都没有：local_var。它是没 export 的本地变量。
  • Git Bash 特有：MSYSTEM、SYSTEMROOT、WINDIR 就算 env -i 也会被 MSYS 运行时补回来。OLDPWD 是 cd / 之前的沙箱目录。

declare -p local_var 显示 declare --，没有 x 标记。对比 export 输出里的 declare -x，x 就是“导出”标记。

打个比方export 表像公司的对外公开名单。printenv 看的是新员工手里那份复印件。名单上挂了名、却没填内容的，复印件里就没有。

考点（答案写在注释里）
diff <(printenv | sort) <(export | sort)   # diff 要两个输入，stdin 却只有一个
                                           # <( ) 把两条命令的输出各变成一个文件名
                                           # 本机实测是 /dev/fd/63 这类
export EMPTY                               # 只标记导出、没赋值：export 里有，printenv 里没有
declare -p local_var                       # declare -- 表示没导出，-x 才是导出

讲义 · Signals and Job Control · 1Git Bash 实测（模拟 pgrep）Linux 未实测

!为什么会在这里踩坑：本机实测踩到的两个坑
现象 1
第一版脚本在 sleep 10000 & 之后，立刻 kill -TSTP %1。jobs 仍显示 Running。接着 bg 报 “job 1 already in background”，pkill 也杀不掉它。

现象 2
pgrep_lf 把测试脚本自己也匹配上了。前提是没跳过 bash 进程。
原因
脚本是用 bash -c '…sleep 10000…' 运行的。这个 bash 的命令行里，也有 “sleep 10000”。真正的 pgrep 有同样的问题。在脚本里用 pgrep -f 时，小心匹配到自己的父进程（补充）。

pgrep -lf "sleep 10000"   # 匹配完整命令行，能精确到参数 10000
pkill -f "sleep 10000"    # 默认发 SIGTERM

练习 7 · wait 只能等自己的子进程，别人的要轮询

讲义 · Signals and Job Control · 2Git Bash 实测

原题：想等一个进程结束，再启动另一个。限制进程是 sleep 60 &。一种办法是用 wait：启动 sleep，让一条 ls 等它结束。但换到另一个 bash 会话里，这招就不灵了。因为 wait 只对子进程有效。有一点课上没讲：kill 成功时返回 0，否则返回非 0。kill -0 不发信号，但进程不存在时返回非 0。写一个 bash 函数 pidwait。它接收一个 PID，一直等到该进程结束。用 sleep 避免白白占用 CPU。

自己的子进程，直接 wait $pid。别的进程就用 kill -0 轮询，每轮 sleep 1 秒，直到它返回非 0。

实测改动

把 sleep 60 缩短成 sleep 3，不然每次生成页面都要干等一分钟。逻辑完全相同。

▶跑：第一部分，wait

时间戳差 3 秒。wait 一直阻塞到后台 sleep 结束，之后 ls 才运行。

{}写：第二部分，pidwait
▶跑

读输出：另一个 bash 里，wait $P 立刻失败了。bash -c 是一个新的 shell 进程。报错是 pid … is not a child of this shell，退出码 127。题目说的情况真实出现了。同一个“外人” shell 里换成 pidwait，就能一直等到 sleep 结束。开始和结束的时间戳差 4 秒。那是 sleep 剩下的约 3 秒，加上最多 1 秒的轮询间隔。

打个比方wait 像父母等自家孩子放学，学校会通知。pidwait 像等邻居家孩子，只能每隔一会儿去门口看一眼。

考点（答案写在注释里）
wait $P                                           # 只对本 shell 的子进程有效，否则报 not a child，返回 127
kill -0 $P                                        # 不发信号，只测进程还在不在
while kill -0 "$1" 2>/dev/null; do sleep 1; done   # pidwait 的核心
# 删掉 sleep 1：循环不停地启动 kill -0，把一个 CPU 核心占满
# sleep 越长越省 CPU，但发现得越晚

原题：进阶题。写一条命令或脚本，递归找出目录里最近修改的文件。更一般地，你能按修改时间列出所有文件吗？

?原理

GNU find 的 -printf 能打印每个文件的元数据。%T@ 是修改时间的 Unix 时间戳，带小数。%p 是路径。%TY-%Tm-%Td %TH:%TM 是人能读的日期。先打印“时间 路径”，再按数值排序。最后一行就是最新的。-printf 是 GNU 扩展，macOS 自带的 BSD find 没有。可以改用 stat，或者装 GNU findutils（补充）。

▶跑

打个比方ls -tR 像每个班各自按身高排队。find 加 sort 像全校站成一排再排。想找全校最高的，只能用后一种。

!为什么会在这里踩坑：ls -tR 不是全局排序
现象

正确写法
让 find 把所有文件压平成一个列表。再统一排序，就是上面的写法。
考点（答案写在注释里）

# 为什么用 %T@ 排：精确到小数秒，同一分钟改的文件也分得出先后
# “2026-01-13 08:15”按字典序排也对，但只精确到分钟

▶跑

第一行说明，Git Bash 里本来没有叫 dc 的命令。在 Linux 上，dc 往往是个真实存在的程序。它是“桌面计算器”，bc 的兄弟。别名会盖过它，这一点没实测。随后在交互式 bash 里定义别名，dc /usr 确实切换了目录。

考点（答案写在注释里）

练习 18 · 带口令的 ed25519 密钥：.pub 能给人，私钥不能

读输出：口令错误时，连本机都解不开私钥，exit=255。口令正确时，-y 从私钥推出公钥，和 .pub 文件开头一致。私钥文件以 -----BEGIN OPENSSH PRIVATE KEY----- 开头，这里只打印了第一行。

!为什么会在这里踩坑：私钥文件的权限

在 Linux 上
私钥权限太宽时，ssh 会拒绝使用。它会提示 “UNPROTECTED PRIVATE KEY FILE!”。要 chmod 600 ~/.ssh/id_ed25519 和 chmod 700 ~/.ssh。这条没实测，是补充。
考点（答案写在注释里）
ssh-keygen -a 100 -t ed25519         # -a 100：用口令派生密钥时，做 100 轮 KDF 运算
                                     # 你解锁慢一点点，攻击者暴力猜口令却要慢 100 倍（补充）
ssh-keygen -y -f ~/.ssh/id_ed25519   # 用口令解开私钥，推出公钥
chmod 600 ~/.ssh/id_ed25519          # Linux 上私钥权限太宽，ssh 会拒绝使用

练习 23 · （挑战）同一会话断网后接着刷新，才算恢复

讲义 · Remote Machines · 6未实测

原题：挑战题。在 VM 里装好 mosh，建立连接。然后断开服务器或 VM 的网卡。mosh 能正确恢复吗？

本机做不了这个实验，下面给出步骤和判断标准。断网再接上后，同一个会话接着刷新。不用重新登录，就算能恢复。

?实验步骤与判断标准
  1. 本机和 VM 都装上 mosh，它需要两端各有一个程序。VM 的防火墙要放行 UDP 60000 到 61000。
  2. 本机运行 mosh vm，它会复用 ~/.ssh/config 的设置。在里面跑 top 这类不断刷新的程序。
  3. 在虚拟机软件里断开 VM 网卡，等 30 秒以上，再接上。
  4. 对照组：用普通的 ssh vm 重复同样的操作。
  5. 判断标准：断网期间，mosh 窗口顶部会提示失去连接。恢复后同一个会话继续刷新，不用重新登录。这就是“能恢复”。ssh 的会话通常会卡住，等到超时断开。

讲义说 mosh 能处理断线和睡眠唤醒。切换网络和高延迟链路，它也扛得住。以上步骤和预期现象是补充说明，本机未实测。

▶跑

打个比方ssh 像打电话，信号一断就得重拨。mosh 像发短信，断网时先攒着，网一回来接着收。

练习 24 · （挑战）-N 不开 shell，-f 认证完转后台

讲义 · Remote Machines · 7参数表实测转发未实测

原题：挑战题。查查 ssh 的 -N 和 -f 是干什么的。想出一条在后台做端口转发的命令。

答案是 ssh -N -f -L 9999:localhost:8888 vm。只开隧道，不开远端 shell，也不占当前终端。

?答案
flag含义（man ssh）
-L 9999:localhost:8888本地转发，和配置里的 LocalForward 同义
-N不执行远端命令。只做转发，不开 shell
-f认证完成后转入后台。认证时可能要你输入口令

命令是 ssh -N -f -L 9999:localhost:8888 vm。如果 ~/.ssh/config 里已经写了 LocalForward，ssh -N -f vm 就够了。结束时用 pkill -f 'ssh -N -f'，这是练习 6 学的。

▶跑

本机 OpenSSH 的用法摘要里，N 和 f 都在无参数选项列表 [-46AaCfGgKkMNnqsTtVvXxYy] 里。

打个比方-N 是只接网线、不开屏幕。-f 是接好线就把机箱塞进柜子，桌面腾出来给你用。

考点（答案写在注释里）
ssh -N -f -L 9999:localhost:8888 vm   # -N 不开 shell，-f 认证完转后台
ssh -N -L 9999:localhost:8888 vm &    # 用 & 不好：一开始就在后台，要输口令时读不到终端
# -f 还会脱离当前 shell 的作业控制，关掉终端也不受影响（补充）
pkill -f 'ssh -N -f'                  # 用完按命令行找到它，结束隧道
